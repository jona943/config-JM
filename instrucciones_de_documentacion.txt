# Estándar de Documentación v3.1

Este archivo define el estándar que sigo para documentar mis cambios, configuraciones y optimizaciones del sistema. El objetivo es mantener un historial personal que sea robusto, organizado por componentes y fácil de auditar en el futuro.

## 1. Tono y Perspectiva

Toda la documentación la escribo en **primera persona** (yo). El tono es el de una bitácora personal, donde narro las acciones que tomé, los problemas que encontré y las soluciones que apliqué.

- **Ejemplo (en vez de):** "Se configuró el sistema para..."
- **Ejemplo (escribir):** "Configuré mi sistema para..." o "Lo que hice fue..."

## 2. Idioma

Toda la documentación debe estar en **español**.

## 3. Estructura de Categorías y Directorios

Para mantener la raíz limpia y organizada, las intervenciones no se colocan en la raíz, sino dentro de una de las 4 categorías principales:

```
hp-db0xxx/
├── 🌐 redes_y_conectividad/       # Wi-Fi, Bluetooth, servicios de red
├── ⚙️ sistema_y_rendimiento/       # Batería, kernel, idiomas del sistema, monitoreo
├── 🖱️ perifericos_y_gestos/        # Touchpad, mouse, conexiones USB/Android
└── 🖥️ aplicaciones_y_escritorio/   # XFCE, Zoom, IDEs, reproductores
```

Dentro de la categoría correspondiente, cada intervención se aloja en su propia carpeta:

`categoria/nombre_descriptivo/`

- **`categoria`**: Una de las 4 carpetas principales (`redes_y_conectividad`, `sistema_y_rendimiento`, `perifericos_y_gestos`, `aplicaciones_y_escritorio`).
- **`nombre_descriptivo`**: Un nombre claro sobre la solución (ej: `wifi_rtl8723de_fix`, `apple_mouse_a1296_fix`).

## 4. Contenido de cada Intervención

Cada directorio de intervención debe contener los siguientes archivos:

### 4.1. README.md (Obligatorio)

Es mi documento técnico principal. Sigo esta estructura:

- `# Título Descriptivo`: Un título personal. Ej: "Cómo Solucioné mi Problema de Wi-Fi".
- `## Propósito`: ¿Qué problema específico estaba tratando de resolver?
- `## Diagnóstico`: Los pasos y comandos que usé para identificar la causa del problema. Incluyo los comandos y sus salidas de texto relevantes.
    ```bash
    # Ejemplo de mi diagnóstico
    sudo dmesg | grep -i error
    ```
- `## Solución que Apliqué`: Los pasos y comandos exactos que ejecuté para implementar la solución.
- `## Verificación`: Los comandos que usé para confirmar que mi solución funcionó.
- `## Cómo Revertir los Cambios`: Cómo podría deshacer los cambios que hice. Si no es posible, explico por qué.

### 4.2. contexto_interaccion.txt / contexto_inicial.txt (Opcional)

Registro cronológico de la interacción o conversación previa que me llevó a la solución.

### 4.3. Archivos de Configuración y Scripts

Cualquier archivo de configuración, script o recurso modificado (`main.conf`, `.desktop`, etc.).
